# Requirements Traceability

This document links product requirements to API, data model, payload schemas,
permissions, stage roadmap, test plan and acceptance criteria. It must be
updated together with `requirements.md`, `interfaces.md`, `api.md`,
`payload-schemas.md`, `data-model.md`, `access-control.md`, `test-plan.md` and
`code-optimization.md` when a change affects engineering quality or the
performance backlog.

## Traceability Maintenance Rules

- A new functional requirement must have at least one API or an explicit explanation of why no API is needed.
- A new write endpoint must have a permission and either idempotent behavior or a `job_id`.
- A new persistent entity must have indexes/uniqueness or an explicit explanation of why they are not required.
- A new roadmap acceptance criterion must reference a capability from the table.
- A new API endpoint must be added to `interfaces.md`, `api.md` and the API authorization matrix in `access-control.md`.
- A new job type must be added to `data-model.md`, `payload-schemas.md` and `test-plan.md`.
